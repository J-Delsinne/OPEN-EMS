Direction 1 · Calm Autopilot — Design Rationale

The homeowner view is a vertical card stack: status line → battery hero → metrics → EV action → strategy. Information is layered in urgency order. The battery circle provides an at-a-glance reading without requiring the homeowner to parse a number. The EV override button is the sole primary action: full-width, 52px, accent color, always in the same position. Degraded mode (not shown in this state) replaces the status line with the slate-colored calm card.

The installer view follows the Stripe/Linear model: dark sidebar navigation, clean content area, three stat cards at the top (peak, battery, grid), device list with connection badges, event log with type badges. The deployment validation uses Vercel-style per-check rows. All log entries use plain-language descriptions, never error codes.

  • Homeowner strengths: hierarchical, scannable, nothing hidden, EV action always visible
  • Installer strengths: professional density, structured, event log is primary diagnostic surface
  • Trade-off: battery circle requires CSS ring; could simplify to a progress bar (see Dir 5)

Direction 2 · Status-First — Design Rationale

The homeowner view opens with a full-width sentence: "Your home is running smoothly." This is the defining message of the autopilot experience — made explicit and primary. Compact metrics sit below in a three-column row; the EV card and strategy follow. Degraded mode replaces the headline sentence and adds the calm slate card below metrics — never intrusive, never alarming.

The installer uses a top navigation bar instead of a left sidebar — better for narrower screens and makes the nav feel less like a settings panel. Content is split into a 2/1 column layout: event log + stats on the left, device list on the right. More compact than Direction 1.

  • Homeowner strengths: sentence-format status is immediately reassuring; minimal cognitive load
  • Installer strengths: top nav saves horizontal space; device list always visible beside content
  • Trade-off: headline sentence needs careful copy for all states (degraded, error, override active)

Direction 3 · Ultra-Minimal — Design Rationale

The homeowner view strips everything to the essential: a large battery percentage as the hero number, a three-metric row, and the EV action. Strategy selection uses pill-style toggle chips instead of a card — much lighter. This direction assumes the homeowner's mental model is simpler than Direction 1 suggests: they primarily want to know the battery and when the EV charges. Everything else is secondary.

The installer view moves to four stat cards and a denser table for devices. Useful for experienced installers who know what they're looking at and prefer maximum information density. Less friendly for first-time setup.

  • Homeowner strengths: fastest possible glance time; no visual noise; feels like a utility tool (positive for some users)
  • Installer strengths: maximum information density; expert-friendly
  • Trade-off: removes battery circle (simpler implementation); large number may feel clinical to some homeowners

Direction 4 · Card Grid — Design Rationale

The homeowner view uses a 2×2 card grid for the four metrics — each card has an emoji icon, a large value, and a plain-language label. The EV override card spans full width below the grid. This layout works particularly well at larger mobile sizes and on tablets. Icons add immediate scannability without technical language.

The installer view shows the role assignment step of the setup flow — making the setup flow itself a first-class UI context rather than showing only the dashboard. Card-based assignment with inline capability detection. Progress stepper in the sidebar shows where the installer is in the flow. This is the clearest representation of the sequential setup experience.

  • Homeowner strengths: grid layout is familiar (widget-style); icons aid quick identification; EV action prominent
  • Installer strengths: best representation of setup flow UX; role assignment is visual and structured
  • Trade-off: emoji icons may feel informal for some; grid may not render as well on very small phones

Direction 5 · Text-First — Design Rationale

The homeowner view uses pure text sections separated by dividers — no circles, no icons, no charts. Each section answers a question in plain English: "System: Running normally / Battery: 81% charged / Solar: Producing 2.1 kW." This is the most accessible and translation-friendly approach. It works perfectly on screen readers and at any font size. The EV button lives directly below the EV section — no card wrapper needed.

The installer view shows the constraint configuration form — the most critical data-entry step in the setup flow. Inline validation (active border on the focused field, green confirmation on valid input), clear field descriptions, and a logical sequence. This direction prioritises functional clarity over visual design.

  • Homeowner strengths: maximum accessibility; no visual noise; language is the design
  • Installer strengths: constraint form is the most realistic depiction of critical data entry
  • Trade-off: may feel austere to some homeowners; no visual hierarchy signals beyond font weight

Direction 6 · Pro Register — Design Rationale

The homeowner view uses a dark top panel for the system headline — giving the status display a distinctive visual anchor. This approach contrasts strongly with the rest of the light UI, making the primary status unmissable. Metrics sit in a compact three-column row below. The EV card includes estimated SOC at end of charging session, giving the homeowner useful contextual information without technical detail.

The installer view showcases the full event log with filtering, search, and the installer note entry. This is the primary remote check-in tool — the log must be scannable, filterable, and include all event types including degraded mode entries. The installer note row shows how Lien would document the Huawei firmware situation for future reference.

  • Homeowner strengths: dark hero panel is visually distinctive and instantly legible; EV estimated SOC adds real value
  • Installer strengths: full event log with search/filter is the most complete view of the installer's primary remote tool
  • Trade-off: dark hero panel requires careful contrast checking; estimated SOC data requires battery + charger integration to be accurate
